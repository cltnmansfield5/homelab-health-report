# Portainer Community

Manage the existing stack through Portainer. Run the Ubuntu helper installer and
rclone setup on the host; a stack deployment does not update the native helper.
Do not start a second Compose project from a host checkout.

## Move an existing stack to this repository

In the existing stack, select **Edit Git settings** and use:

- Repository: https://github.com/cltnmansfield5/homelab-health-report
- Reference: refs/heads/main
- Compose path: compose.yaml

Keep the existing stack name, environment variables and host data paths. Add the
private settings below before redeploying; the public repository has generic
defaults. Save with **Redeploy** unchecked while you refresh the native helper,
then use **Pull and redeploy** with **Re-pull image** disabled. The images build
from the selected checkout. Existing evidence, uploader state and credentials
remain in the same host directories.

[Portainer documents editing Git settings](https://docs.portainer.io/user/docker/stacks/edit#edit-git-settings).
If your version lacks that control, keep the working stack while choosing a
migration method; do not detach it from Git just to change the repository URL.

## Stack settings

Use this repository's compose.yaml on Docker Standalone. It builds local images
from the selected revision; rebuilding is required for code/config changes.
Generic TOML defaults are included in the images, avoiding Git-relative bind
mounts that depend on [Portainer Business Edition](https://docs.portainer.io/advanced/relative-paths).

Enter these variables in the stack, or load the locally generated .env:

| Variable | Value |
| --- | --- |
| HH_UID / HH_GID | Dedicated account IDs generated by prepare-host.sh |
| DOCKER_GID | Group ID of the actual Docker socket |
| HH_DATA_DIR | /var/lib/homelab-health unless you deliberately migrated it |
| DOCKER_SOCKET | /var/run/docker.sock for the supported installation |
| HH_HOSTNAME | Generic fallback; fresh helper status supplies the host identity |
| HH_TIMEZONE | Your IANA timezone, such as America/Denver |
| HH_DRIVE_REMOTE | Existing name from rclone listremotes, without the colon |
| HH_INBOX_FOLDER_ID | Your private Inbox folder ID |
| HH_REPORTS_FOLDER_ID | Your private Reports folder ID |

~~~bash
id homelab-health
stat -c 'DOCKER_GID=%g permissions=%a' /var/run/docker.sock
rclone listremotes
rclone config file
~~~

Only the gateway receives DOCKER_GID. Never make the socket world-writable or
publish port 2375. OAuth tokens belong only in the host credential file.
[Portainer documents environment-variable entry](https://docs.portainer.io/user/docker/stacks/add).

## Upgrade from the initial personalized configuration

**Before redeploying**, copy the existing Drive remote and both folder IDs from
your current private config into the three HH_DRIVE_* / HH_*_FOLDER_ID settings
listed above. Also set HH_TIMEZONE to preserve the collection schedule and
HH_HOSTNAME for the fallback. Keep existing UID/GID, data-directory and socket
values. This release removes personal defaults from the repository.

Select a reviewed revision, then pull and redeploy the existing stack.
For this local-build setup, leave “Re-pull image” disabled so Compose builds the
selected checkout. Its [build policy](https://docs.docker.com/reference/compose-file/services/#pull_policy)
reuses unchanged layers. A container restart alone does not update its image.

Update the native helper from that same checkout during a short collection
maintenance window:

~~~bash
sudo systemctl stop homelab-health-host.service
sudo bash scripts/prepare-host.sh
sudo systemctl start homelab-health-host.service
~~~

The installer preserves /etc/homelab-health/host.toml and private-redactions.txt.
The new clock/job checks and SMART identifier suppression require this helper
update; rebuilding the containers alone is insufficient.

## Verify

For the [Drive text fallback](text-transport.md), rebuild/redeploy the existing
uploader from the reviewed revision. No new environment variables or helper
restart are required. Existing local archives backfill automatically; wait for
`transport-<sha256>.ready.md` and an uploader status of `ok: true`. Keep the
existing outbox, state, and credential mounts. Check the part-progress fields
while a backfill is running.

In Portainer, check gateway, collector and uploader health and their recent logs.
On the host:

~~~bash
sudo cat /var/lib/homelab-health/host/status.json
sudo cat /var/lib/homelab-health/collector-state/status.json
sudo cat /var/lib/homelab-health/uploader-state/status.json
~~~

Confirm a new archive and matching .ready.json reach Inbox. A gateway 502 calls
for socket path/GID checks. A config IsADirectoryError indicates a mistaken file
bind mount. Empty Drive IDs or a wrong remote name stop uploads. Preserve queued
evidence when diagnosing retries.

If Portainer cannot build the Git context, build both Dockerfile targets from
the reviewed host checkout, use pull_policy: never for that deployment, and
redeploy through Portainer. Keep the same existing stack and data paths.
